# K-MATCH 서비스 기획서

## 얼굴보다 먼저, 대화로 만나는 글로벌 데이팅 서비스

-   문서 버전: v0.1
-   단계: 1단계 클릭 가능한 데모
-   주요 타깃: 한국 남성 × 한국에 관심 있는 해외 여성
-   1차 테스트 국가: 일본
-   향후 확장: 몽골, 우즈베키스탄, 카자흐스탄 등
-   핵심 차별점: 사진/스와이프보다 **1:1 대화를 먼저 시작**하고, 서로
    다른 언어를 자동 번역해 주는 경험

------------------------------------------------------------------------

# 1. 프로젝트 한 줄 정의

> **얼굴보다 먼저 대화하고, 언어 장벽 없이 서로를 알아가는 글로벌 1:1
> 데이팅 서비스**

일반 데이팅 앱처럼 사진을 보고 좋아요를 누르는 것이 아니라,

**대화 상대 탐색 → 1:1 대화 → 자동 번역 → 서로 호감 확인 → 프로필/사진
공개**

순서로 관계가 발전한다.

------------------------------------------------------------------------

# 2. 가장 중요한 제품 원칙

## 2.1 Face First가 아니라 Conversation First

기존:

`사진 → 좋아요 → 매칭 → 채팅`

K-MATCH:

`관심사/언어 → 대화 → Connect → 프로필 공개`

핵심 메시지:

> **얼굴보다 먼저, 대화.**

보조 문구 후보:

-   먼저 이야기해보세요.
-   Swipe less. Talk more.
-   다른 언어, 같은 대화.
-   내 언어로 말하고, 상대의 언어로 만나다.

------------------------------------------------------------------------

# 3. 1단계 데모의 목표

1단계에서는 실제 회원가입/서버/결제/인증을 만들지 않는다.

목표는 단 하나다.

> **처음 보는 사람이 3분 안에 서비스의 핵심 가치를 이해하고 실제 앱처럼
> 클릭해볼 수 있도록 만든다.**

### 데모에서 반드시 가능한 것

-   시작
-   국가/언어 선택
-   가상 프로필 생성/확인
-   대화 상대 탐색
-   하루 10명 대화 제한 표시
-   대화 시작
-   1:1 채팅
-   자동 번역 UI
-   원문 보기
-   Connect
-   프로필 공개
-   지나간 상대 보기
-   신고
-   차단
-   신고 접수 결과
-   이용 제한 상태 예시
-   Premium 버튼(실제 결제는 하지 않음)

------------------------------------------------------------------------

# 4. 1단계에서 하지 않을 것

다음 기능은 2\~3단계로 미룬다.

-   실제 회원가입
-   실제 OAuth
-   실제 DB
-   실제 사진 업로드
-   실제 본인 인증
-   실제 성인 인증
-   실제 번역 API
-   실제 푸시 알림
-   실제 결제
-   실제 관리자 서버
-   실제 AI 스캠 탐지
-   실제 위치 추적
-   실제 앱스토어 배포

단, **나중에 구현할 것을 고려한 데이터 구조와 화면 구조는 처음부터
설계한다.**

# 11. 대화 시작 방법

대화 시작의 진입장벽을 낮추기 위해 "오늘의 질문"을 제공한다.

예:

-   한국에 가면 가장 먼저 하고 싶은 것은?
-   가장 좋아하는 한국 음식은?
-   여행할 때 바다와 산 중 어느 쪽을 좋아하나요?
-   서로의 나라에서 꼭 먹어봐야 할 음식은?
-   좋아하는 영화는?
-   주말에 보통 무엇을 하나요?

버튼:

`이 질문으로 대화 시작`

``` text
User A
  ↕
Conversation
  ↕
User B
```

# 13. 자동 번역 UX

## 원칙

메시지는 항상 **원문을 기준 데이터로 저장**한다.

화면에서는 수신자의 언어에 맞는 번역을 우선 표시한다.

예:

``` text
Yuki 🇯🇵

한국 음식을 정말 좋아해요!

[원문 보기]
韓国料理が大好きです!
```

한국 사용자가 보내면:

``` text
민준 🇰🇷

韓国に来たら、美味しい店を紹介します。

[원문 보기]
한국에 오면 맛있는 곳을 소개해줄게요.
```

------------------------------------------------------------------------

# 14. 번역 데이터 원칙

Message에는 원문만 저장한다.

Translation에는 번역 결과를 저장한다.

예:

``` text
MESSAGE
id: msg_001
sender_id: user_101
original_language: ja
original_text: 韓国料理が大好きです!
```

``` text
TRANSLATION
message_id: msg_001
target_language: ko
translated_text: 한국 음식을 정말 좋아해요!
```

같은 원문 + 같은 언어의 번역 요청이 다시 발생하면 캐시를 활용한다.

------------------------------------------------------------------------

# 15. 번역 캐시

향후 실제 서비스에서는 비용 절감을 위해 번역 캐시를 사용한다.

권장 논리:

``` text
메시지 입력
  ↓
원문 저장
  ↓
translation cache 검색
  ↓
존재함 → 저장된 번역 사용
  ↓
없음 → 번역 API 호출
  ↓
번역 결과 저장
  ↓
사용자에게 표시
```

주의:

같은 문장이라도 문맥에 따라 번역이 달라질 수 있으므로 단순히 전체
서비스의 문자열만 보고 캐싱하지 않는다.

초기에는:

`source_language + target_language + normalized_text`

를 캐시 키 후보로 사용하고, 향후 품질 문제를 확인한다.

------------------------------------------------------------------------

# 16. 하루 대화 상대 제한

무료 사용자는 하루에 최대 10명의 **서로 다른 사람**과 새로운 대화를
시작할 수 있다.

중요:

-   메시지 개수가 아니라 상대방 수를 센다.
-   같은 사람과 여러 메시지를 주고받아도 1명이다.
-   대화를 종료하고 다시 시작해도 당일 사용량은 복구되지 않는다.
-   하루가 지나면 새로운 대화 한도가 다시 10명으로 시작한다.

화면:

``` text
오늘의 대화
7 / 10명

오늘 3명의 새로운 사람과
대화할 수 있어요.
```

10명 사용:

``` text
오늘의 새로운 대화를 모두 사용했어요.

내일 다시 10명과 대화할 수 있습니다.

[ 더 많은 대화 이용하기 ]
```

Premium 버튼만 먼저 구현하고 실제 결제는 추후 구현한다.

------------------------------------------------------------------------

# 17. 향후 Premium

1단계에서는 결제하지 않는다.

향후 후보:

-   하루 대화 상대 추가
-   하루 10명 → 30명
-   더 많은 대화권
-   무제한 대화
-   고급 검색
-   번역 관련 추가 기능
-   프로필 노출 우선권

단, 가격과 기능은 실제 사용자 테스트 후 결정한다.

# 18. 신고 시스템

신고는 현재 대화 상대뿐 아니라 **지나간 상대도 신고 가능**해야 한다.

예:

``` text
지난 대화

Yuki
Aiko
Mio

[ 상대 프로필 ]
  ↓
[ 신고하기 ]
[ 차단하기 ]
```

대화 종료 후에도 일정 기간 신고할 수 있도록 한다.

기본 정책 후보:

-   일반 신고: 종료 후 90일
-   심각한 안전 문제: 별도 처리
-   실제 서비스 출시 전 법률/안전정책 검토

------------------------------------------------------------------------

# 19. 신고 사유

필수 선택형:

-   사기/금전 요구
-   다른 사람의 사진 사용
-   사칭
-   성적인 메시지
-   성적인 이미지 요구/전송
-   욕설/괴롭힘
-   협박
-   스토킹/만남 강요
-   미성년자로 의심됨
-   광고/스팸

추가 설명 입력 가능.

------------------------------------------------------------------------

# 20. 신고 제한

일반 신고는 악용 방지를 위해 제한한다.

후보 정책:

-   하루 최대 3건
-   월 최대 10건

단, 심각한 안전 문제는 별도 신고 경로를 고려한다.

같은 사용자가 같은 상대를 여러 번 신고해도 "서로 다른 신고자 수"를
별도로 계산한다.

------------------------------------------------------------------------

# 21. 신고 누적 제재

단순히 "10번 신고 = 자동 유죄"로 처리하지 않는다.

권장:

``` text
신고 접수
 ↓
신고 사유/중복/신고자 확인
 ↓
위험도 계산
 ↓
관리자 검토
 ↓
조치
```

후보 정책:

-   최근 24시간 동안 서로 다른 이용자의 중대한 신고가 반복되면 우선 검토
-   최근 30일 신고가 10건 이상이면 자동 관리자 검토
-   실제 정책 위반이 확인되면 최대 30일 이용정지
-   중대한 위반은 즉시 제한/영구정지 가능
-   허위·악의적 신고를 반복하는 신고자도 제재

------------------------------------------------------------------------

# 22. 차단

신고와 차단은 독립 기능.

차단하면:

-   상대방이 메시지를 보낼 수 없음
-   새로운 대화 시작 불가
-   추천 목록에서 제외
-   서로의 프로필 탐색에서 제외

상대방에게 "누가 차단했다"는 사실을 직접 알리지 않는다.

# 24. 스캠 방지

향후 탐지할 수 있는 이상 행동:

-   가입 직후 대량 좋아요/대화 시작
-   여러 사용자에게 동일 문장 반복
-   매우 빠른 외부 메신저 이동 유도
-   금전/투자/송금 요구
-   반복적인 계정 생성
-   신고가 여러 명에게서 집중됨
-   프로필 사진/소개가 반복됨
-   비정상적인 대화량

AI가 바로 영구정지하지 않는다.

권장:

`자동 탐지 → 위험 신호 생성 → 관리자 검토 → 제재`

```text
대화 지속
        ↓
Connect
        ↓
프로필/사진 공개
```

즉, 사용자는 **사람을 고르는 것보다 먼저 대화를 고른다.**

네 번째:

> **처음에는 단순하게 만들고, 실제 사용자 행동을 보고 확장한다.**

# 126. 1단계 개발 시작 프롬프트

Claude Code에 처음 전달할 때는 다음 방향으로 시작한다.

```text
이 프로젝트는 "한남일녀(HNY)"라는 이름의
Conversation First 글로벌 데이팅 서비스 1단계 클릭 가능한 데모다.

가장 중요한 제품 원칙은:
"얼굴보다 먼저, 대화."

일반적인 데이팅 앱처럼 사진을 보고 스와이프하는 UI를 만들지 않는다.

사용자는 먼저 대화 주제를 선택한다.

예:
음식 & 카페
여행
음악
영화/드라마
게임
동물
한국 문화
취미/운동
일상
자유 대화

주제를 선택하면 오늘의 질문을 보여준다.

질문을 선택하면 해당 주제와 관심사가 잘 맞는 가상 상대를 추천한다.

상대 사진은 대화 전에는 잠겨 있다.

사용자가 대화를 시작하면 1:1 채팅으로 들어간다.

채팅 메시지는 Mock 자동 번역을 사용한다.
번역 결과를 기본으로 보여주고 원문 보기 기능을 제공한다.

일정 수준의 대화 후 Connect 기능을 제공한다.

서로 Connect하면 상대의 프로필과 사진을 공개한다.

사용자는 하루 최대 10명의 새로운 상대와 대화를 시작할 수 있다.

같은 상대와 여러 번 메시지를 주고받아도 1명으로 계산한다.

지난 대화 상대에게도 신고와 차단이 가능하다.

신고에는 사유 선택과 추가 설명이 있다.
```
