# 0. 문서 목적

이 문서는 Claude Code가 프로젝트를 구현할 때 사용할 수 있는 **단일 기준 문서(MASTER SPEC)**다.

- 서버 없음
- 실제 로그인 없음
- 실제 결제 없음
- 실제 번역 API 없음
- 실제 본인 인증 없음
- 실제 신고 처리 서버 없음
- Mock 데이터 사용
- 브라우저에서 실제 앱처럼 클릭 가능해야 함

단, 이후 실제 서비스로 확장할 때 필요한 데이터 구조와 기능은 처음부터 확장 가능하도록 설계한다.

# 2. 서비스 철학

일반적인 데이팅 앱:

사진 → 평가 → 좋아요 → 매칭 → 채팅

한남일녀:

**대화 주제 → 관심사 → 사람 → 채팅 → Connect → 프로필/사진**

핵심 차별점:

1. 사진보다 대화가 먼저다.
2. 사람보다 이야기 주제를 먼저 선택한다.
3. 언어가 달라도 자동 번역으로 대화할 수 있다.
4. 번역을 끄고 상대 언어를 직접 읽을 수 있다.
5. 언어를 배우려는 사람과 좋은 인연을 찾는 사람의 목적을 구분한다.
6. 대화가 잘 맞으면 사진과 프로필을 단계적으로 공개한다.
7. 신고와 차단은 과거 대화 상대에게도 가능하다.

# 20. 자동 번역

## 번역 ON

원문 + 번역을 함께 보여준다.

```text
今日はカフェに行きました！

오늘 카페에 갔어요!
```

## 번역 OFF

원문만 보여준다.

```text
今日はカフェに行きました！

[ 번역 보기 ]
```

번역 보기 클릭 시:

```text
오늘 카페에 갔어요!
```

---

# 21. 번역 설정은 사용자별

중요:

사용자 A가 번역 OFF라고 해서 사용자 B도 OFF가 되는 것은 아니다.

예:

```text
민준
일본어 → 한국어
번역 OFF

Yuki
한국어 → 일본어
번역 ON
```

각 사용자가 독립적으로 설정한다.

# 22. 언어 학습 모드

1단계에서는 간단히 번역 OFF + 번역 보기로 구현한다.

2단계 이후:

> 🇯🇵 일본어 연습 모드

기능 추가 가능.

예:

```text
昨日は友達と映画を見ました！

```

번역을 먼저 보지 않고 이해해보도록 유도한다.

향후 확장:

- 단어 뜻 보기
- 발음 보기
- 표현 저장
- 자주 사용한 표현
- 간단한 언어 학습 통계

단, 학습 앱처럼 무겁게 만들지 않는다.

# 23. 번역 데이터 구조

메시지는 원문을 기준 데이터로 보존한다.

```text
Message
- id
- conversationId
- senderId
- originalText
- originalLanguage
- createdAt
```

번역:

```text
Translation
- id
- messageId
- targetLanguage
- translatedText
- translationProvider
- createdAt
```

같은 문장/같은 목표 언어의 번역 결과는 캐싱한다.

목표:

**동일 번역을 반복 호출하지 않는다.**

# 24. 대화 이어가기

채팅이 잠시 멈추면:

```text
💡 이야기를 계속해볼까요?

Yuki는 여행을 좋아한다고 했어요.

[ 일본에서 가장 좋아하는 여행지는 어디예요? ]

[ 다른 질문 ]
```

1단계:

- 미리 준비된 질문

2단계:

- AI 기반 질문 생성

AI 질문 생성은 실제 대화 내용을 필요 이상으로 저장하지 않도록 개인정보 최소화 정책을 함께 설계한다.

---

# 25. Connect

일정 시간/메시지 이후 자연스럽게 제안한다.

```text
💛 이 사람과 더 이야기하고 싶나요?

서로 Connect하면
프로필과 사진을 확인할 수 있어요.

[ Connect ]

[ 아직은 괜찮아요 ]
```

좋아요가 아니라 Connect를 사용한다.

의미:

> 사진을 보고 선택하는 것이 아니라
> 대화를 해본 뒤 더 알아가고 싶다는 의사 표현.

기존 상대와 여러 번 대화하는 것은 추가 차감하지 않는다.

예:

```text

8 / 10
```

새로운 상대와 최초 대화를 시작할 때만 +1.

결제 기반 추가 대화 기능은 향후 구현.

1단계에서는 UI만 만들어도 된다.

# 31. 신고

신고 이유:

- 금전 요구 / 사기
- 가짜 프로필
- 다른 사람 사진 사용
- 사칭
- 성적인 메시지
- 성적인 사진 요구
- 욕설 / 괴롭힘
- 협박
- 스토킹 / 만남 강요
- 외부 메신저 이동 강요
- 광고 / 스팸
- 미성년자로 의심됨
- 기타

가능하면 관련 메시지를 신고 근거로 첨부한다.

# 32. 신고 정책

초기 아이디어:

> 하루 3회 / 한 달 10회 이상 신고 → 한 달 이용정지

실제 서비스에서는 이 숫자를 **자동 유죄 판정 기준으로 사용하지 않는다.**

권장:

```text
신고 누적
 ↓
위험도 상승
 ↓
자동 모니터링 강화
 ↓
관리자 검토
 ↓
위반 확인
 ↓
경고 / 일시 정지 / 영구 제한
```

이유:

- 악의적 허위 신고 가능
- 집단 신고 가능
- 신고만으로 위반을 확정할 수 없음

심각한 행위는 신고 수와 관계없이 즉시 제한할 수 있다.

- 새 메시지 수신 불가
- 새로운 대화 시작 불가
- 검색/추천에서 제외

차단은 신고와 별도로 가능하다.

자동 정지보다 **위험 신호 생성 + 관리자 검토**를 기본으로 한다.

# 52. UI/UX 원칙

## 원칙 1

사진을 첫 화면의 주인공으로 만들지 않는다.

## 원칙 2

버튼을 많이 만들지 않는다.

## 원칙 3

한 화면에 하나의 핵심 행동.

## 원칙 4

가입은 최대한 짧게.

## 원칙 5

번역은 자동이지만 사용자가 언제든 끌 수 있어야 한다.

## 원칙 6

연애 목적을 상대방이 확인할 수 있어야 한다.

## 원칙 7

신고/차단은 과거 상대에게도 접근 가능해야 한다.

## 원칙 8

AI가 모든 것을 결정하지 않는다.

## 원칙 9

MBTI를 궁합 판정 도구로 사용하지 않는다.

## 원칙 10

언제든 안전하게 대화를 종료할 수 있어야 한다.

# 56. 최종 제품 정의

한남일녀는 단순한 국제 데이팅 앱이 아니다.

**핵심 경험은 다음과 같다.**

> 한국에 관심 있는 사람이 앱에 들어온다.
>
> 사진을 먼저 고르지 않는다.
>
> 오늘 이야기하고 싶은 주제를 고른다.
>
> 그 주제를 좋아하는 사람을 만난다.
>
> 서로 다른 언어로 대화한다.
>
> 번역이 도와준다.
>
> 원하면 번역을 끄고 상대의 언어를 직접 읽는다.
>
> 대화가 잘 맞으면 Connect한다.
>
> 그때 서로의 사진과 프로필을 조금 더 알아간다.

**가볍게 시작하지만, 관계가 깊어질수록 더 많은 정보가 공개되는 구조다.**

# 57. Claude Code 초기 지시문

아래 문장을 Claude Code에 첫 지시로 사용할 수 있다.

```text
이 문서(MASTER_PROJECT_SPEC.md)를 프로젝트의 기준 사양으로 사용해.

목표는 한남일녀라는 모바일 우선 웹 프로토타입을 만드는 것이다.

1단계에서는 실제 서버, 인증, 결제, 번역 API, AI API를 만들지 않는다.
모든 데이터는 Mock 데이터로 구현한다.

가장 중요한 UX는 다음이다.

"얼굴보다 먼저, 대화."

사용자는 사진을 먼저 평가하지 않는다.
오늘 이야기하고 싶은 주제를 선택하고,
그 주제에 관심이 있는 상대와 대화를 시작한다.

핵심 플로우:

Welcome
→ Demo User
→ Onboarding
→ MBTI
→ 관심사
→ 한국 관심 이유
→ 만남 목적
→ 오늘의 대화 주제
→ 오늘의 질문
→ 상대 추천
→ 1:1 채팅
→ 번역 ON/OFF
→ 번역 보기
→ 대화 이어가기
→ Connect
→ 사진 공개
→ 대화 목록
→ 지난 대화
→ 신고/차단

만남 목적은 다음 3개다.

🗣️ 언어교류
💛 좋은 인연
🌏 둘 다

이 목적은 프로필에 표시하고 추천 로직에도 반영한다.

하루 새로운 대화는 10명까지다.
이미 대화한 사람과 계속 대화하는 것은 제한 횟수에 포함하지 않는다.

사진은 초기에는 잠겨 있으며,
서로 Connect한 경우 공개한다.

채팅은 1:1만 지원한다.
그룹 채팅은 구현하지 않는다.

번역은 사용자별 설정이다.
한 사용자가 번역을 OFF해도 상대방의 번역 설정은 영향을 받지 않는다.

번역 ON:
원문 + 번역 표시

번역 OFF:
원문 표시 + "번역 보기" 버튼

코드는 모바일 우선으로 작성한다.
컴포넌트는 재사용 가능하게 작성한다.
Mock 데이터는 나중에 Supabase로 교체하기 쉽게 별도 파일/계층으로 분리한다.

작업을 시작하기 전에 프로젝트 구조를 제안하고,
그 다음 단계별로 구현해라.
한 번에 모든 것을 만들지 말고,
각 단계가 실행되는 상태에서 다음 단계로 넘어가라.
```
